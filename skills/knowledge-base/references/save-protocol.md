# 知识沉淀规范

## 触发约定（每次解决问题后必做）

每次问题解决后，Agent 必须**主动提醒用户判断是否沉淀**，不能等用户开口，也不能擅自写入：

```
问题解决
  │
  └─ Agent 主动问：「这个问题要沉淀到知识库吗？」
        ├─ 给出判断依据（新问题类型？已有覆盖？一次性环境问题？）
        ├─ 用户拍板：
        │     ├─ 要 → 按下方「写入流程」执行
        │     └─ 不要 → 跳过，本次结束
```

目的：避免用户遗忘沉淀，也避免知识库被一次性问题污染。

## 触发条件

问题解决后，检查以下条件决定是否写入知识库：

### ✅ 应该记录
- 知识库中完全没有的新问题类型
- 已有问题的新的解决方案或变体
- 新的命令参数组合或使用技巧
- 新的错误场景及其根因
- 环境/版本差异导致的特殊处理

### ❌ 不应记录
- 知识库已有且完全覆盖 → 告知用户已有记录
- 文档中已写明的基础命令 → 不需要重复
- 一次性的环境问题（磁盘满、网络断等）→ 不属于 conda 知识域
- 用户明确表示不需要记录

## 写入流程

```
问题解决
  │
  ├─ 1. 判断：值得记录？
  │     ├─ 否 → 跳过
  │     └─ 是 → 继续
  │
  ├─ 2. 定位：哪个文档最合适？
  │     参考 SKILL.md 中的路由表
  │     如果跨多个类别，选最核心的那个
  │
  ├─ 3. 检查：该文档是否已有类似内容？
  │     ├─ 已有 → 追加为子章节（### 开头）
  │     └─ 全新 → 作为新的顶层章节（## 开头）
  │
  ├─ 4. 写入：按 references/doc-format.md 模板格式
  │
  ├─ 5. 截图：需要保存用户截图？
  │     ├─ 是 → 先确认用户同意
  │     │       保存到 ~/.claude/knowledge/conda/screenshots/
  │     │       在文档中引用：![描述](screenshots/xxx.png)
  │     └─ 否 → 跳过
  │
  ├─ 6. 更新索引：在 index.md 中添加或确认关键词条目
  │
  └─ 7. 确认：告知用户已沉淀到哪个文件
```

## 注意事项

- 不要覆盖用户的原始笔记内容，只在末尾追加。
- 追加前先 Read 目标文档的最后 50 行，确认不重复。
- 如果用户提供的截图包含敏感信息（IP、密钥等），提醒用户脱敏后再保存。
