# 知识库健康检查

## 触发时机

每次沉淀新知识后（save-protocol 步骤 6），执行一次轻量检查。

## 检查项与阈值

### 层级 1：领域数量

| 指标 | 健康 | ⚠️ 警告 | 🔴 需优化 |
|------|------|---------|-----------|
| INDEX.md 中领域数 | ≤20 | 21-50 | >50 |
| 单个领域 index.md 中文档数 | ≤15 | 16-30 | >30 |

### 层级 2：文档大小

| 指标 | 健康 | ⚠️ 警告 | 🔴 需优化 |
|------|------|---------|-----------|
| index.md 行数 | ≤50 | 51-100 | >100 |
| 单个知识文档行数 | ≤200 | 201-400 | >400 |

### 层级 3：路由精度

| 指标 | 健康 | ⚠️ 警告 | 🔴 需优化 |
|------|------|---------|-----------|
| 关键词重复命中（两个文档匹配同一关键词） | 0 | 1-2 | >2 |
| index.md 中关键词总数 | ≤50 | 51-100 | >100 |

## 检查方式

```bash
# 领域数
grep -c "^\|" ~/.claude/knowledge/INDEX.md

# 文档行数
wc -l ~/.claude/knowledge/<domain>/*.md

# 重复关键词检测（人工判断，无法自动化）
```

## 优化策略（按优先级）

### 策略 A：拆分大文档
- 单文档 >200 行 → 拆分为多个子文档
- 更新 domain index.md 增加细分关键词

### 策略 B：合并冗余
- 多个文档覆盖相似主题 → 合并 + 保留精华
- 删除纯通用知识（模型已知的内容）

### 策略 C：索引瘦身
- index.md >50 行 → 精简关键词，去掉太宽泛的
- 关键词 >100 个 → 按使用频率去重

### 策略 D：数据库存储（最后手段）
- 适用场景：领域 >50、文档 >500、全文检索需求
- 方案：SQLite + MCP Server 或向量数据库
- 成本：需要开发 MCP Server，Claude 无法直接查询
- 对比文件方案：
  - 文件方案：Claude 原生 Read，Git 可版本管理，简单直观
  - 数据库方案：需要中间层，增加复杂度，但支持全文检索和模糊匹配

> **建议：** 先尝试策略 A/B/C，绝大多数情况不需要数据库。文件方案在 500 个文档以内表现良好。

## 报告格式

当阈值触发时，输出如下报告：

```
⚠️ 知识库健康检查告警

问题：linux/network.md 已 320 行（阈值 200）
建议：拆分为 network-basics.md（基础）和 network-perf.md（性能调优）

问题：INDEX.md 已有 55 个关键词（阈值 50）
建议：精简宽泛关键词，合并相似条目
```
